추가 성공 기준은 [발더스 게이트 70% 수준의 전체 플레이 흐름](product-success.md)이며,
그래픽이 아니라 선택·결과·후속 진행의 연결을 기준으로 평가한다.
현재 결과는 초기 수직 슬라이스이며 전체 제품 완료로 판정하지 않는다.

지속 세계와 동적 콘텐츠는 현재 최종 목표에 포함한다. 이전 계획의 “MVP 이후”는 구현 순서이며 제외를 뜻하지 않는다.
원본에서 제외한 멀티플레이·계정·전체 D&D 클래스·거대 오픈월드는 자동 추가하지 않는다.

## 이번 안정성 개선

- 판정·이벤트·상태를 먼저 commit하고 이후 서사를 생성한다.
- 서사 실패는 상태를 되돌리지 않으며 기본 서사와 실패 상태를 저장한다.
- 서사 저장이 실패하면 이미 commit된 결과를 반환한다. pending 상태에서 프로세스가 죽은 턴의 자동 서사 재생성은 아직 미구현이다.
- 캠페인 조건부 UPDATE의 rowcount를 직접 검사한다.
- OpenAI 서사 오류 시 DeepSeek를 시도하며, 잘못된 응답 구조와 proposal은 엔진 전달 전에 거부한다.
- 테스트는 실제 키 대신 가짜 공급자와 임시 DB를 사용한다.

## 재접속 복구 완료조건

2026-09-21 아래 기계 상태 복구 조건은 확장 Chrome 검사·서버 회귀·Sol 독립 검토를 통과했다.

- 전송 전에 원래 요청 ID·캠페인·상태 버전·입력·결말 확인값을 브라우저에 보관한다.
- 응답 유실 여부를 알 수 없으면 새 행동이나 저장 복원으로 덮어쓰지 않고 같은 요청을 재시도한다.
- 서버 처리 전 연결 실패와 commit 후 응답 유실을 각각 실제 브라우저에서 재현한다.
- 새로고침 후에도 같은 요청으로 복구하며 사건·자원·주사위는 중복 적용하지 않는다.
- 다른 탭에서 진행한 최신 캠페인을 오래된 재생 결과로 퇴행시키지 않는다.
- 이것은 기계 상태 복구이며 pending 서사의 자동 재생성이나 event replay 완성을 뜻하지 않는다.

다음 구현 순서는 재현 가능한 RNG/규칙 → 모험·NPC 지식 → UI/지도 → 장기 기억/세계 tick → 장시간 품질 검증이다.
각 단계의 테스트 통과를 최종 제품 완료로 간주하지 않는다.
